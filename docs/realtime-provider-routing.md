# 实时行情主备路由

## 当前架构

`RealtimeProviderRouter` 位于 Qt 工作线程，业务层只接收统一的 `MarketDataProvider` 事件。默认候选为公共 TDX 固定主源、固定备用源、腾讯公开行情异构备用源和最后启动的 TDX 自动发现源；同一时刻只运行一个 Provider，避免对 5000+ 股票重复采集。可用 `PPTRADER_TDX_PRIMARY_SERVER`、`PPTRADER_TDX_BACKUP_SERVER` 覆盖固定端点，旧 `PPTRADER_TDX_SERVER` 仍作为主源兼容配置。

候选声明 providerId、名称、transport、优先级、配置、全市场、原始逐笔、原生分钟 K、最小周期、轮询间隔和授权能力。当前业务最低粒度明确为 1 分钟，不要求 Tick 级接入；公共 TDX 和腾讯都只产生行情观测，不进入 9C 原始成交事实入口。

腾讯全市场适配器通过 HTTPS 每 60 秒顺序分批拉取沪深报价，北交所仍排除。另有独立的 `TencentMinuteBarService` 仅请求主页当前选中品种的真实 1 分钟 OHLCV，并只更新内存模型；它不写 SQLite、不进入历史 catalog，也不参与回测数据身份。报价返回时间按 `Asia/Shanghai` 转 UTC，休市时使用最后真实报价时间，不能用下载完成时间冒充实时；相同全市场报价时间不会重复落库。

## 健康、熔断与恢复

- Error 立即熔断；低于 90% 完整率的连续 3 个已完成批次触发切换。
- 30 秒没有状态、Tick 或快照事件视为静默。批次内每条 Tick 都刷新 watchdog，长批次不会被误判。
- 高于等于 90% 但存在缺失时保持 `Degraded`，继续服务并降低评分，不伪装 Healthy。
- 熔断冷却为 60 秒。所有候选都在冷却时发布 Error；候选冷却结束后自动重试。
- 备用源接管后不主动抢回主源；重启行情任务时重新按优先级选择，避免运行中抖动。

分钟轮询候选可以声明独立 watchdog；腾讯使用 150 秒，避免 60 秒正常轮询被全局 30 秒规则误切换。评分范围 0–100，综合结构化健康、完整率、连续严重失败和静默时长。它不是交易所延迟或生产 SLA。

## 2026-08-09 实测

备用端点受控探测执行 200 只、2 轮采集，均收到 200 只，单轮源耗时 229–277 ms。全市场故障注入把主端点设为不可达回环端口；watchdog 切换后，备用源完成 5156/5207 只快照，完整率 99.0%，界面显示 `公共 TDX 备用源 [备用] · degraded · 评分 70`。65 秒运行中备用源保持可用，截图位于 `artifacts/realtime-router-10f/`。

本验证证明事件门控、故障切换和 5000+ 批次可工作，但不是长时间稳定性承诺。公共 TDX 无 SLA，仍可能限流、断连或缺失。

腾讯公开端点探测请求 5317 个缓存代码，返回 5226 个有效报价，完整率 98.29%；67 个批次总耗时 18.65 秒，批次 p95 269.1 ms。应用以实际沪深股票池运行时完成 5207/5207、100% 快照并显示评分 100；休市场景 Provider 保持 Healthy，但快照独立显示 stale。腾讯接口没有面向本项目的正式授权合同或 SLA，因此只作为公开异构备用源。

副屏证据位于 `artifacts/tencent-realtime-10f/`。同日串行 Debug 全量构建成功，CTest 17/17、`all_qmllint` 与 Python 脚本语法检查通过；自动测试不访问真实网络。

## 后续生产化

- 若后续需要生产 SLA，增加 QMT/miniQMT 或持牌专业行情适配器，保持同一能力与路由接口；不再以逐笔为本项目硬要求。
- 对 4 小时以上连续运行记录 p50/p95 延迟、完整率、断线恢复和写库积压。
- 增加可配置端点与凭据存储 UI；凭据进入系统安全存储，不写 SQLite。

`PPTRADER_TENCENT_ENABLED=0` 可禁用腾讯候选；`PPTRADER_REALTIME_PROVIDER=tencent`/`tdx` 可用于单源诊断，正常运行建议留空并由 Router 自动选择。

实时分钟与历史 Tick 的永久边界见 `docs/realtime-and-historical-data-boundary.md`。
