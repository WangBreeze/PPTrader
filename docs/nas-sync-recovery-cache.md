# NAS 同步恢复与暂存管理

## 恢复契约

H1C 将当前 NAS 同步计划原子保存到应用数据目录的版本化 JSON。文件只包含用户明确查询得到的代码、交易日、摘要、相对下载路径、逐项状态和耗时，不保存端点、Token、主机、账户或远端仓库路径。恢复时要求代码为六位数字、版本与 SHA-256 一致，且路径严格等于 `/v1/ticks/代码/YYYYMMDD`；被篡改或错配的条目在联网前拒绝。应用启动只读取该本地状态，不访问 NAS；退出时仍处于下载或导入中的条目恢复为“已取消、可重试”，成功项不会重复处理。

用户仍需配置有效节点并点击“重试未完成”才会联网。新 catalog/manifest 会显式替换旧计划。状态文件使用 `QSaveFile` 原子提交，限制为 16 MiB、12000 项；版本、字段或摘要校验失败时拒绝恢复并显示错误，不执行部分计划。

## 暂存缓存

校验通过的 CSV 位于 Qt `CacheLocation/nas-tick-staging/YYYYMMDD/代码.csv`。下载前继续比较文件大小和 SHA-256；完全匹配时复用并计入 `cacheHits`，不重新传输。页面仅在用户点击“刷新缓存统计”时扫描该目录，并显示受管 CSV 数量和字节数。

“清理 30 天前”也是显式操作。清理只处理一层 `YYYYMMDD/[0-9]{6}.csv`、跳过符号链接和无关文件，并按文件最后修改时间删除过期项；不会删除 SQLite 中的 Tick 事实、派生 K 线或回测归档。查询或同步运行期间拒绝清理。

## 验证边界

Qt Test 使用临时目录覆盖原子 round-trip、运行中状态恢复、损坏 JSON 拒绝、队列重试、缓存统计和保留期清理。缓存管理不自动下载、不自动清理，也不等同于完整断点续传；分块续传、摘要索引缓存和生产 NAS 监控仍属于后续阶段。
