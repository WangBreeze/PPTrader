# 设计与工程治理

## 设计依据

页面的整体视觉、布局层级和交互意图以 Figma 为准；QML 负责忠实实现经确认的页面。工程中的真实数据能力、性能边界和桌面窗口行为优先于示意数据：设计与实现冲突时，更新 Figma 说明，不为迁就示意稿虚构数据或接口。

## 主页面固定约束

主页面保留两张核心图表，不能以摘要卡替代。

1. **实时品种图表**：独立选择实时 A 股品种，展示行情 Provider 的在线、停止、陈旧和错误状态。数据来自实时/行情快照链路，不承诺无 Provider 时仍有实时值。
2. **回测品种图表**：独立选择回测品种，只使用本地历史数据。必须显示“本地数据”标识、周期、可用 K 线数量和缓存时间；无本地数据时显示空状态并引导加载，不可伪造可回测结果。

当前工程的本地数据库仅确认包含 `600519` 的日线 500 根样本；设计应支持日后扩展到任意已缓存 A 股，而非把示例误标为全市场可用。

## 导航与标题栏

顶层工作区采用“主页、市场快照、指标与策略、回测任务、执行中心”五个入口。指标与策略保留左侧二级抽屉；回测任务和执行中心提升为一级入口。当前实现使用五个路由入口和三个常驻页面实例，保持回测、审批、筛选和加载状态；不要仅为文件名对齐而复制 Controller 状态。页面跳转、标题栏状态、窗口控制和 Provider 控制按 Qt 桌面应用实际能力设计；若与旧稿不同，应在 Figma 标注“业务派生”。

## 交付约定

每个页面设计在实现前应标出数据来源、加载/空/错误状态和对应入口。Figma 截图经视觉核验后，开发任务才可进入 QML 实装；任何新增属性先由 C++ `TradingController` 定义，再暴露给 QML。
