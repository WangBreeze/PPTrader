# A 股策略研究工程审查（2026-09-07）

## 结论与范围

现有工程可以复用为策略研究平台，但**尚不应以参数排名认定策略盈利**。必须先修正成交价格、T+1、组合清仓与扫描结果真实性，再接入多股基线、策略内日频选股／分时入场和多指标候选策略研究。按用户更正，多个指标组成一个策略，各策略运行实例独占自己的资金与持仓；不开发此前误述的多策略共享账户。

本次审查对象为当前 Windows 工作区，包括未提交文件；参考 HEAD 为 `560ad5f1cf455e38d0a8da5933bb4f57ab1fa95c`，不是仅审查该提交的差异。检查了策略注册／DSL、单股与组合执行、参数搜索、研究入口和已有真实数据证据。下列复现为源码路径分析及确定性场景推演，**本轮没有执行构建、CTest 或页面交互测试**，也没有访问 NAS、行情网络或运行数据库；既往测试通过不等于下列场景已覆盖。

“bug修复”任务已接收实时分钟节拍 `MARKET-004` 二次诊断；策略审查不修改它负责的实时业务代码。本报告列出独立回测修复队列，避免与实时修复同时改动公共模块或并行构建。

## 必须修复的发现

### STRAT-R01 · P1：下一根开盘成交实际使用收盘价

- 证据：`src/strategy/CustomBacktestStrategy.cpp:113` 在下一根 Bar 以 `candle.open` 设置策略参考成本并发出买入信号；`src/services/BacktestEngine.cpp:462` 却固定取当前 `candle.close`，未按成交模式解析价格。旧扫描器使用的 `src/services/BacktestEvaluator.cpp:105` 也固定取 close。
- 场景：触发后的下一根 `open=105、close=110`，零费用／滑点时实际成本为 110，策略止盈止损参考成本却为 105，资金、数量和退出条件不一致。
- 修复要求：用明确的信号时刻与成交时刻／模式契约统一正式引擎和扫描器；不要简单信任任意策略给出的价格而绕过合法报价检查。
- 回归：完整引擎验证 nextOpen 的实际成交、数量、费用及后续止损。已有 `tests/tst_custom_strategy.cpp:783` 只检查策略信号价格，不能证明账户成交正确。

### STRAT-R02 · P1：周期 K 回测结束强平绕过 T+1

- 证据：`src/services/BacktestEngine.cpp:729` 将末日禁止平仓限定为 `rawMode`。`src/strategy/CustomStrategyValidator.cpp:309` 要求 A 股自定义策略启用 T+1，但 Candle 模式结束时仍可强平当天新仓；旧 `BacktestEvaluator.cpp:189` 也直接平掉剩余持仓。
- 场景：同日分钟 Bar 买入，策略依法延迟退出，结束回测时却产生同日卖出；日线样本末日买入亦受影响。
- 修复要求：执行层统一卖出资格，不能仅依赖策略自行检查；末日不可卖仓位保留并按市值计入权益，不伪造成交。内置周期策略也应受相同市场规则约束。
- 回归：当日新仓、前日可卖仓、跨日、日线／分钟线／RawTicks、未平仓结果序列化及正式／扫描摘要一致性。

### STRAT-R03 · P1：正滑点可能导致组合全清仓一股不卖

- 证据：`src/services/PortfolioExecutor.cpp:59` 用市值差除以滑点后成交价求卖量；第 62 行在结果超过持仓时直接跳过。
- 场景：持有 200,000 股，价格 10 元，滑点 0.1%，每手 100，目标权重 0。原式得到 200,200 股，大于可卖持仓，整笔被跳过。
- 影响：轮动剔除、风险熔断和归零目标均可能无法退出。
- 修复要求：分清目标持仓量与成交现金，卖量不能超过真实可售量；全清仓和受 T+1 限制的剩余仓位分别处理。不能只修改目标权重后宣称已清仓。
- 回归：非零滑点、大持仓、归零／部分减仓、熔断、可售不足；核对实际成交和最终持仓。

### STRAT-R04 · P1：无效参数被当成 0% 收益参与排名

- 证据：`src/services/ParameterGridScanner.cpp:77` 编译失败后加入默认摘要，第 80 行把收益记为 0%；第 95 行按收益降序。`ParameterGridResult` 没有成功状态或失败原因字段。
- 场景：有效参数回测为 -3%，另一候选参数编译失败，界面排名会把无效候选列在前面，无法区分失败与真实空仓。
- 修复要求：显式记录 succeeded／failed／cancelled、原因、有效交易数量；失败项保留审计但不得进入收益排名或被选为胜者。有效但零交易的策略另标记为无交易证据。
- 回归：全亏损、混合失败、全部失败、零交易、取消以及序列化／界面显示。

### STRAT-R05 · P2：网格在限额检查前完整展开，且 UI 再次展开

- 证据：`src/services/ParameterGridScanner.cpp:53` 先构造全部组合，第 58 行才检查上限；`src/app/TradingController.cpp:8014` 为进度文案在主线程再次调用 `expandGrid`。
- 场景：六轴各 20 值可先生成 64,000,000 个参数映射，512 上限不能保护分配阶段；展开时尚未检查取消，可能卡住界面、耗尽内存或妨碍退出。
- 修复要求：校验轴名称、数值与去重；用防溢出的乘积在分配前检查预算，采用有界／惰性遍历，UI 只展示已校验的计数，不重复展开。
- 回归：超限、空轴、重复轴、非有限数、计数溢出、展开前取消和界面响应。RawTick 敏感性已有独立限额，不能据此认定旧链路安全。

### STRAT-R06 · P1：参数扫描页面调用不存在的字符串方法

- 证据：`qml/components/ParameterGridPanel.qml:32`–34 调用 `trimmed()`；QML JavaScript 字符串使用 `trim()`，这里不是 C++ `QString`。两种扫描入口都会经过 `parseAxis`。
- 场景：点击自定义 K 线或原始 Tick 扫描时，读取文本参数即会触发方法不存在错误，后端调用无法抵达。
- 修复要求：使用正确的字符串处理并对无效输入明确报错，不静默删掉错误候选。
- 回归：QML 实际创建并调用两种入口，覆盖空白／合法／非法数值；再启动可见应用确认页面和按钮工作。仅 C++ 扫描测试或 qmllint 不足。

### STRAT-R07 · P2：拒绝买入后，策略仍误认为已持仓

- 证据：`src/strategy/CustomBacktestStrategy.cpp:130` 发信号前更新 `m_hasPosition`；`src/services/BacktestEngine.cpp:495` 因不足一手拒绝成交时，没有成交／拒绝反馈修正策略状态。nextOpen 分支也存在相同问题。
- 场景：固定预算 1,000 元、100 股一手，价格 11 元首次入场失败；随后价格 9 元、条件仍满足，策略因误认为有仓而不再买入。
- 修复要求：信号、订单意图、成交和实际持仓分离，由执行结果更新所属策略运行实例的仓位相关状态；反馈不能改变其他策略的独立账户。
- 回归：不足一手后恢复可买、手续费／滑点导致拒绝、仓位上限、重复信号和取消。

## 可复用能力与缺口

| 方向 | 已有实现 | 仍不能据此宣称的能力 |
| --- | --- | --- |
| 基线策略 | 注册表含 SMA、RSI、MACD、BOLL 四类周期策略及四类 raw-only Tick 策略，参数和数据模式明确 | 不等于八种策略已具备可靠盈利证据，也不等于已导入并核对开源策略来源 |
| 多股批量 | 单一 strategyId 对多个独立数据集执行，有界并发／输入驻留、结果身份及状态 | 独立实验不能冒充一个选股策略的股票组合；多候选比较也必须保持各自账户 |
| 横截面 | 对齐数据、RANK／Top-N、目标权重、单策略内股票组合账户、风险约束、因子研究 | 还没有同一策略内日频选股与 RawTick／分钟进场的双频联动契约 |
| 原始 Tick 搜索 | 尾部留出、嵌套 walk-forward、训练选参、独立验证、候选／数据哈希 | 不是跨策略结构、股票和周期的统一搜索治理 |
| 旧自定义 K 线搜索 | 单股最近最多 2,000 根、单策略参数扫描 | 仍按同一段收益排序，没有独立训练／验证划分；不能沿用原始 Tick 链路的样本外结论 |
| 多重检验 | 因子研究已有显式候选集的 Holm／BH 校正 | 不覆盖任意策略穷举，也不能将因子 IC 校正直接当作交易策略收益可信度 |
| 自定义策略 | 受限 DSL、版本、向导、验证与归档 | 不能把任意外部 Python 策略直接当作安全插件执行 |

已有 C++ 插件激活后进入模拟 `StrategyEngine`，不是自动进入回测注册表；导入开源参考仍需明确的回测适配、版本／许可记录与能力校验。DSL 已有多指标条件组合，符合用户“多指标组成一个策略”的方向；应复用并补齐独立账户的完整路径验证，而不是新建跨策略共享账户。

其他模型边界：当前 triggerClose 和部分横截面交易采用完整 Bar 生成信号后按同根 close 成交的理想化假设；费用主要是比例佣金／滑点。执行模块虽有交易所规则服务，但上述回测路径未全面复用其停牌、价格限制等能力。真实收益研究需要版本化费税、可售数量、交易状态及成交容量假设，不能把理想化撮合收益等同于可复制实盘收益。
