# 原始 Tick 展示权益曲线有界化（H3B.19）

## 结论

`BacktestEngine` 仍对每条原始 Tick 顺序执行策略、持仓估值、收益率统计和最大回撤计算，但 `BacktestResult.equityCurve` 不再必然保存每条观测。原始 Tick 超过 8192 条时，结果只保留有界展示序列，并强制包含首点、末点和最大回撤点；周期 K 线模式继续一根 K 线对应一个权益点。

绩效摘要不从采样曲线反推。最终权益、总收益和最大回撤来自全部观测的精确状态；夏普使用全部相邻权益收益的在线均值与样本方差。样本结束平仓会替换最后一次收益观测，避免手续费和滑点只进入成交而漏出绩效统计。

## 数据契约与归档

- `equityObservationCount`：参与精确绩效计算的完整观测数。
- `equityCurveSampled`：当前 `equityCurve` 是否为展示采样。
- QML 的 `backtestResultConfiguration` 同时暴露完整观测数、展示点数和采样标记；结果身份区明确提示“绩效按全部观测计算”。
- SQLite schema 保持 v24。归档仍保存展示权益点、完整成交/摘要和 v19+ 不可变输入快照；恢复时依据 `actualBars` 与展示点数重建采样元数据，旧归档保持兼容。

## 验证

确定性 12,000 Tick fixture 在一次性与分日流式两条路径下都得到 6,002 个展示点，低于 8,192 上限；两条路径的数据 SHA-256、最终权益、收益、最大回撤和夏普一致。与改动前未采样基线相比，最终权益、收益和最大回撤一致，夏普差异约 `5.5e-14`，属于在线浮点累积顺序差异。归档测试验证采样结果写入临时 SQLite 后可恢复 3 条完整 Tick、2 个展示点和正确元数据。

2026-08-30 串行 Debug 完整构建通过，CTest 43/43（74.68 秒）通过，`all_qmllint` 通过。本阶段未访问 NAS 或外网；12,000 条是确定性回归样本，不冒充真实跨月性能验收。

## 边界

采样只解决逐 Tick 权益点的长期驻留。成交与策略信号仍按真实事件保存；显式归档工作线程仍会暂时物化完整 Tick 输入。固定留出、多折和参数敏感性仍存在多遍输入需求，真实跨月数据仍受质量门控。当前展示算法是确定性步长采样并保留关键点，不是 LTTB 等视觉形状优化；如需更高保真，应在不改变精确摘要和不可变身份的前提下独立演进。
