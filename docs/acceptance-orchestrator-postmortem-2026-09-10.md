# 2026-09-10 盘中验收未启动复盘

## 结论

本次失败发生在 PPTrader、TDX 和真实网络门禁启动之前。冻结候选、Qt 运行库、Provider 和业务代码都没有进入执行，因此不能据此判断行情链路失败，也没有任何盘中验收结果。

直接原因是把“次日 09:25 启动”实现成了 Codex 会话下长期休眠的 PowerShell 子进程。原编排器 PID `28916` 与恢复编排器 PID `27516` 都在等待阶段、约 6～6.5 小时后被外部结束，脚本自己的异常捕获没有执行。第二次恢复仍沿用了同一长驻等待方式，所以没有消除故障模式。

## 证据边界

- PID `28916` 于 2026-09-09 19:46:19 启动；2026-09-10 02:18:47 前已消失，存活上界约 6.541 小时。
- PID `27516` 于 2026-09-10 02:18:47 恢复；08:30:42 仍在，08:48:03 前已消失，存活区间约 6.199～6.488 小时。
- 两个进程最后状态均为 `waiting_preflight`；stdout/stderr 为 0 字节，没有 `failure.txt`，也没有预检目录、正式目录、PPTrader 或 TDX bridge。
- Windows 系统/应用日志未发现对应时段的重启、睡眠或 PowerShell 崩溃。
- 同环境探针确认 Codex 启动器和其 PowerShell 子进程都位于 Windows Job 中。因此“宿主 Job/租约回收长驻子进程”是与证据最一致的高置信解释；宿主内部的精确超时值没有可见证据，不能写成已证明事实。

## 设计问题

1. 将临时会话子进程当成跨夜调度器，生命周期与验收目标不匹配。
2. 第一次中断后的恢复只更换 PID，没有更换调度机制。
3. 原自动跟进任务可以观察文件和进程，但按安全约束不能在未证明网络权限继承时自行重启真实探针；它不是可靠的开盘启动器。
4. 状态文件只有阶段，没有周期租约，无法在进程被外部结束时留下明确的最后存活时间。
5. 启动脚本没有锁定应用二进制和 Qt 运行库，无法保证“发生修复则使用 Qt 6.11.2”的版本规则。

## 修复

- 新增 `scripts/register_limit_up_strategy_market_task.ps1`：由短命令注册 Windows 任务计划，在 09:25 门禁前 60 秒启动，不再让 Codex 子进程跨夜休眠。
- 任务使用当前交互用户、`Limited` 权限、`IgnoreNew` 单实例策略和 8 小时执行上限；错过注册截止后拒绝补跑，避免盘后伪造正式覆盖。
- 注册时固定 `PPTrader.exe`、Qt 根目录、QtCore 版本和应用 SHA-256；下一次因代码变化而进行的正式验收固定使用 Qt 6.11.2 独立 Release。
- 非 DryRun 注册必须填写本次真实网络授权引用并写入任务证据；没有明确授权记录时拒绝创建任务。
- 编排器和正式启动器都拒绝早于目标窗口 10 分钟的直接启动；编排器每 30 秒更新 `orchestrator-lease.json`。
- 应用启动后核对实际加载的 `Qt6Core.dll` 路径；不一致时关闭精确应用 PID 并失败，不继续生成正式证据。
- PPTrader 启动环境显式清除 NAS 凭据变量；本调度器不访问 NAS、不写实时事实表、不提交订单。
