## 范围与结论

对照现有 Figma 的[策略管理主界面](https://www.figma.com/design/YFTuHENpOe71mzWh8006OH/PPTrader?node-id=2094-2)、[单股回测子窗口](https://www.figma.com/design/YFTuHENpOe71mzWh8006OH/PPTrader?node-id=2094-3)、[参数微调与版本快照](https://www.figma.com/design/YFTuHENpOe71mzWh8006OH/PPTrader?node-id=2094-4)，检查当前 QML、`TradingController`、归档和日志链路。本次只做开发前调研，未修改业务代码，也未运行新 UI。Figma 实时设计上下文受到当前账号的调用额度限制；下述画板判断基于此前保存的三张静态画板。如果画板已经变更，实施前需要重新核对。

**结论：视觉规范和既有策略能力可以沿用，但画板不能原样无缝接入。** 当前回测的选股、任务、结果及归档选择集中在一个 `TradingController` 上。新子窗口若直接绑定这些属性，会互相覆盖选股和结果；启动下一次回测还可能取消正在运行的任务。必须先建立按窗口区分的回测会话，再接入新页面。

## 推荐接入边界

1. 在现有「指标与策略」页内增加策略管理区域，继续使用 `PPTheme` 和共享控件。顶层导航与窗口结构保留一个来源，避免嵌套两套导航。
2. 控制器提供 `BacktestSession`（或等价的会话模型）：`sessionId`、策略 ID/版本、定义校验值、股票、周期、数据集身份、费用、当前 `taskId`、运行状态、进度、结果 `resultId`、错误。QML 仍只通过 `TradingController` 发起操作，会话对象只向窗口提供可观察状态。
3. 独立窗口绑定自己的会话对象。选择股票只改变该会话；执行任务时冻结策略定义、参数和数据集。数据准备及回测完成消息通过请求 ID 和任务 ID 回到对应会话；关闭窗口不隐式取消任务，取消操作要显式执行。并发上限或排队策略应在会话服务中统一规定。
4. 归档保存 `sessionId`、策略定义快照或校验值及现有数据版本等复现信息；旧归档按兼容方式读取，不能把缺失校验值显示成已验证。
5. 网格扫描产生候选配置，用户选中候选值后创建下一版本草稿。真实收益展示必须注明样本区间；训练与验证区间的边界先定下来，再把画板上的该区域接到实际结果。

## UI 点击与流程日志

现有 `LogService` 提供线程安全、按大小轮转的本地文件日志；默认在应用目录 `logs/pptrader.log`，也可由 `PPTRADER_LOG_PATH` 指定。`TradingController::setStatusText()` 会去重并记录状态文案。检查到的策略、选股、归档和导航 QML 操作没有统一的语义点击日志，状态日志也无法还原一次点击到异步结果的完整过程。

推荐在控制器提供统一的 UI 行为记录入口，复用 `LogService` 的 `ui` 类别。每条记录为机器可解析的结构化数据，包含：UTC 时间、单调序号、`interactionId`、`sessionId`、页面与稳定控件 ID、行为 ID、输入方式（鼠标/键盘/无障碍）、策略 ID/版本、股票、`taskId`、`resultId`、阶段（`intent`、`accepted`、`rejected`、`completed`、`failed`、`cancelled`）、耗时和错误码。首阶段可以把 JSON 作为现有日志的一条消息写入；读取和过滤工具应按 `ui` 类别及关联 ID 查询。

优先记录这些行为：选择策略版本、保存新版本、打开/关闭回测窗口、选择股票、启动/取消回测、打开归档、启动扫描、采用扫描候选值。QML 在**语义动作入口**发 `intent`；控制器在校验与任务状态改变时记录后续阶段。不要仅在全局鼠标事件中打点，否则会漏掉键盘和无障碍操作，也无法区分一次点击是否被接受。`PpButton` 的鼠标、键盘、无障碍路径最终都触发 `clicked()`，接入时要只写一条意图日志，并保留现有焦点及禁用按钮的悬停说明行为。列表和选择框需在有效选择时记录，避免绑定初始化被当作用户点击。

日志不记录策略源码全文、输入框逐键内容、凭据、用户本地路径或原始行情。失败事件记录可定位的错误码与简短原因；详细错误仍可在原有服务日志中查找。一次点击和最终归档必须能用同一个 `interactionId`、`sessionId`、`taskId` 与 `resultId` 串起来。

## 实施顺序与验收

1. **会话与结果契约**：先实现独立会话和异步请求路由，再让两个窗口分别选择不同股票回测；其中一个窗口的选择、取消、关闭均不能覆盖另一个窗口或主界面结果。
2. **策略管理与快照**：将画板主界面嵌入现有内容区，接通版本选择、复制新版本、归档回放和定义校验值；历史归档缺失字段有明确提示。
3. **微调与日志**：固定训练/验证边界，接通候选值到新版本；关键操作记录完整的 `intent → accepted/rejected → completed/failed` 链路。
4. **界面验收**：检查主窗口 1600×1000、1120×760，子窗口 1280×850、1120×760 的布局；鼠标、键盘与无障碍各触发一次操作时只生成一条意图日志。执行 `all_qmllint`、相关 CTest、实际主窗口加载和正常退出检查。
5. **真实回测验收**：使用 `~/.data` 的历史数据、冻结的策略版本及数据版本运行至少两只股票；保存结果后重启读取，核对会话、任务、归档和日志关联。真实表现需要区分训练、验证区间，不能由示例数据替代。

本调研没有执行 Qt 6.12 的 GUI、APP-001 或盘中/长稳验收，因此不对这些运行门槛作通过声明。
