## 已确认与尚未确认

已确认：

1. 慢退出发生在服务已停后的 QML 对象销毁，而非本次本地查询停止阶段；修复早前查询积压并未覆盖此问题。
2. 两份本地 Qt PDB 栈再次指向 `QQuickScrollBar` → `QObject` → `ConnectionData::removeConnection`。CPU仍前进并最终退出，不是“没有窗口所以程序已经结束”。
3. 当前 Qt 6.4.3 源码的 `QPlatformAccessibility::setActive` 每次转发通知；`QQuickScrollBar::accessibilityActiveChanged(true)` 无去重地连接 increase/decrease 动作；QObject 调试版的移除连接包含链表遍历校验。重复连接和调试版放大有具体源码依据。
4. 官方 **v6.8.0** 的上述激活/ScrollBar两个函数仍有同类形态。不能以“Qt 6.8”这个版本名保证消除；本轮未检查全部后续补丁版本或运行6.8二进制。

尚未确认：重复连接是否足以单独解释本次全部耗时，以及重复激活的真实次数/连接总数。需要最小单引擎正常 UI 生命周期复现，验证重复动作不放大，再回到真实向导；现有探针同时保留早先的独立 QQmlEngine，不能据此把所有测试入口特征当作生产架构。外部 UIA 保留 COM 对象的旧 APP-003 和本次重复连接风险不能未经验证合并为同一根因。
