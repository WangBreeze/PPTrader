# H3B.23 原始 Tick 异步流式归档

## 结论

显式归档延迟原始 Tick 结果时，`AsyncBacktestArchiveService` 不再先构造覆盖整个日期范围的 `QVector<RawTradeTick>`。独立 SQLite 工作线程在一个事务中按交易日顺序读取 `raw_trade_ticks`，逐条写入 `backtest_raw_ticks`，随后写入权益与成交。界面线程、Controller requestId 门控和现有 QML 契约不变。

## 身份与事务边界

- 归档前、逐日读取后及提交前复验事实数与内容 SHA-256；执行数据版本、总条数、首末时间任一不一致即拒绝。
- 图表信号按时间戳和同时间戳出现顺序绑定原始 Tick；未匹配信号会使整个归档失败。
- 父结果、完整原始 Tick 快照、信号、权益曲线和成交明细共用单一事务。读取、身份或子表写入失败都会回滚，不留下半个结果。
- `rawTickResidencyChanged(requestId, residentTicks)` 仅用于测试和性能观测，不表示归档进度，也不暴露给 QML。
- 已物化原始 Tick 结果和 Candle 归档继续走原路径；SQLite schema 保持 v24。

## 可重复验证

测试先以缺少驻留信号形成红灯，再使用临时 SQLite 的 8 个交易日 fixture 验证 9/12/15/18/21/24/27/30、合计 156 条 Tick。流式写入峰值驻留为 1，结束回到 0；恢复后仍有完整 156 条原始事实、原信号、相同首末时间和执行 SHA-256。既有“身份变化拒绝且无半归档”测试继续通过。

2026-08-30 最终结果：Debug 串行全量构建成功，CTest 43/43（74.52 秒），`all_qmllint` 通过；隔离临时数据库的副屏原生关闭探针 PID 20736 以 0 退出。本阶段未访问 NAS、外网或开发机业务数据库。

## 尚未覆盖

该 fixture 证明驻留契约，不是跨月真实归档耗时或进程内存验收。归档仍不可取消，超大事务持续时间和 SQLite 文件增长待真实准入数据复验。本文记录的“显式加载仍一次性恢复完整 `rawTicks`”是 H3B.23 完成时的历史状态，已由 2026-08-30 的 H3B.24 默认轻量恢复与存储层分页契约替代；QML 逐笔归档浏览仍未实现。
