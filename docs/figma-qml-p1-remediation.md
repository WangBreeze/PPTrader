# Scene Graph 完成后的 P1 视觉与可访问性修复规格

> 页面：`PPTrader / A股全市场时刻股价`  
> Figma：`fileKey=YFTuHENpOe71mzWh8006OH`，`nodeId=26:972`  
> 基准画板：1600×1000  
> 本文性质：下一轮实施的精确补丁合同；本轮不修改 QML、C++ 或 Figma

## 1. 结论与边界

本轮只收口已经确证的 P1：时刻控制区和主按钮、图表工具栏、底部图例、窄窗响应式、键盘焦点和禁用原因提示。Scene Graph 的点层、数据契约、导出、多窗口、自动刷新逻辑和新视觉风格均不在本补丁范围。

Figma 节点已通过 Desktop Bridge 只读复核，当前导出仍为 1600×1000 原始画板、0.98×预览、PNG 163329 bytes。本文不要求、也不允许为了本补丁再次调用已触顶的官方 `get_design_context`。

坐标口径：

- “画板坐标”以 1600×1000 客户端内容左上角为 `(0,0)`，不含 Windows 标题栏和窗口边框。
- “组件局部坐标”以对应卡片左上角为 `(0,0)`。
- Figma 只定义 1600×1000 正常态；窄窗换行、焦点环和禁用提示属于 Qt 必需派生，但必须复用现有颜色、字体、圆角和边框，不能改变 1600×1000 默认截图。

## 2. 两类修复的判定规则

### A. 必须严格匹配 Figma

- 1600×1000 下的坐标、尺寸、间距、文案和选中态。
- 允许误差：一级容器与控件外框不超过 1 px；文字抗锯齿不作逐像素相等要求。
- 不得用压缩按钮、缩小字号、删减文案或改变图例顺序来“近似适配”。

### B. Qt 可访问性/响应式必须新增

- 焦点环、可访问名称/描述、禁用原因可读、窄窗换行。
- 新增表现不得占用布局尺寸，不得改变非焦点默认态，不得引入新颜色、阴影、图标或动画。
- 静态截图只能确认视觉；键盘顺序、屏幕阅读器语义和禁用提示必须通过运行态测试确认，本文不宣称完整 WCAG 合规。

## 4. P1-02 主按钮：尺寸与状态不跳动

来源：默认态为**严格匹配 Figma**；busy/focus/disabled 为 **Qt 必需派生**。

“应用时刻并刷新”在所有状态保持 `166×38`、圆角 6、字号 11/Bold，不能因为“正在查询…”或窗口变窄而改变宽度。

| 状态 | 表现 | 行为 |
| --- | --- | --- |
| 默认 | 实心 `#21B6E9`；文字 `#0B0F14`；1 px 边框与填充同色 | 可点击；只由该按钮提交草稿时刻 |
| hover | 不改变尺寸；允许边框/亮度使用现有 cyan 体系 | 不触发提交 |
| pressed | 不移动控件，不新增阴影；可使用现有颜色轻微压暗 | 单次提交 |
| busy | 文案“正在查询…”；保持 166×38；整体约 45% 不透明度 | 禁止重复提交；请求完成后恢复 |
| disabled | `textMuted` 语义、整体约 45% 不透明度 | 不触发业务动作；禁用原因仍可读 |
| keyboard focus | 见 P1-06 的外焦点环 | Enter/Space 与单击一致 |

禁止通过把主按钮恢复为 146 px 后再增加外部空白来通过坐标验收；可见矩形本身必须为 166 px。

## 7. P1-05 窄窗响应式：只换行，不缩控件

来源：**Qt 必需派生**。Figma 没有窄窗画板，以下规则以不破坏 1600×1000 为前提，并复用全部现有控件。

### 7.1 断点

| 页面宽度 | 模式 | 时刻卡 | 右侧摘要 |
| --- | --- | --- | --- |
| `width >= 1600` | Figma 严格模式 | `h=92`，全部单行，使用第 3 节坐标 | 固定 318 px |
| `1360 <= width < 1600` | 时刻区换行 | `h=148`；输入/快捷时刻留在第一行，分时/播放/应用移到第二行 | 仍固定 318 px；主图宽度至少 986 px，容纳标题与 570 px 工具栏 |
| `1120 <= width < 1360` | 紧凑桌面模式 | 同为 `h=148`，不再缩小按钮或字号 | 摘要折叠为 318 px 右侧抽屉；主图占满左右 20 px 内空间 |

当前窗口最小宽度为 1120，本补丁不新增更小宽度。摘要保护断点取 1360，而不是等到 1280，原因是摘要常驻时主图宽度为 `windowWidth-374`；570 px 工具栏要与 360 px 标题保留至少 16 px 间距并保留右内边距 20，主图至少需要 986 px，即窗口至少 1360 px。这个派生断点不改变 Figma 宽屏截图，同时完整覆盖已确证的 `<1280` 问题。断点比较应只有一个状态源，避免时刻卡与摘要分别判断出互相冲突的模式。

### 7.2 148 px 换行卡的精确规则

第一行保持日期、时刻、时区和五个快捷按钮的 1600 基准 x、宽度、8 px gap 与 30/38 px 可见高度，不缩放。

第二行目标：

- 分时标题：局部 `x=cardWidth-520,y=80`。
- 轨道：局部 `x=cardWidth-520,y=108,w=250,h=4`；手柄 14×14。
- 09:30/15:00：顶边局部 `y=120`，分别与轨道左右边缘对齐。
- 播放：局部 `x=cardWidth-252,y=92,w=54,h=38`。
- 应用：局部 `x=cardWidth-186,y=92,w=166,h=38`。
- 轨道到播放的水平间距仍为 18；播放到应用为 12；应用到卡右为 20。
- 在最小卡宽 1080（窗口 1120）时，第二行分别从 x=560/828/894 开始，应用结束于 x=1060，保留 20 px 右边距。

页面纵向关系必须由卡高推导，不写第二套魔法数：

```text
mainArea.y = timeControls.y + timeControls.height + 16
mainArea.height = page.height - mainArea.y - 16
```

本 P1 的宽度验收使用高度 1000。现有 760 px 最小高度下是否引入页面纵向滚动属于另一项垂直响应式决策，不在本补丁中顺带实现，也不能用压缩 Plot 来掩盖。

### 7.3 响应式禁止项

- 不隐藏日期、时刻、快捷时刻、分时、播放或应用按钮。
- 不引入新菜单、图标、抽屉内容或新的响应式视觉语言。
- 不缩小 Noto Sans SC 字号、按钮高度、主按钮宽度或 36×36 最小命中区。
- 不改变板块过滤后的全市场 X 槽位语义。

## 8. P1-06 键盘焦点：不改变默认截图

来源：**Qt 可访问性必须新增**。

### 8.1 通用按钮

- 可见按钮保持原尺寸；焦点环绘制在可见矩形外侧 2 px，1 px cyan，透明填充，圆角为可见圆角 +2。
- 可见矩形与焦点环之间保留 1 px 背景色隔离，保证 primary/active cyan 控件仍能看见焦点。
- 焦点环只在键盘导航产生的 focus-visible 状态出现；鼠标点击后不强制常驻。
- 外环使用覆盖层绘制，不参与 `implicitWidth/implicitHeight`，不得让相邻控件位移。
- 28/30 px 可见按钮保持至少 36 px 高命中区；38 px 按钮沿用 38 px 命中高度。
- Enter 和 Space 触发一次 `clicked`；焦点态不得与 hover、active 共用唯一视觉信号。
- 可访问语义：`name=text`、`role=Button`；有 `toolTip` 时同时作为 description。

### 8.2 输入框与滑块

- 日期输入的可访问名称为“日期”，时刻输入为“时刻”，不要依赖相邻视觉标签推断。
- TextField 聚焦时保留现有 cyan 内边框，并增加与按钮一致的外焦点环；不改变 148×38/132×38。
- Slider 可访问名称为“分时定位”，值文本按 `HH:mm` 暴露；左右键使用现有 5 分钟步长。
- Slider 聚焦时在 250×34 控件外绘制同规则焦点环；手柄仍为 14×14。

### 8.3 Tab 顺序

宽屏和换行模式均按视觉阅读顺序：

```text
日期 → 时刻 → 开盘 → 10:30 → 午后14:00 → 收盘15:00 → 当前
→ 分时定位 → 播放（启用时） → 应用时刻并刷新
→ 图表工具栏 → 图表交互层 → 板块筛选/摘要
```

禁用控件可以从操作型 Tab 顺序中跳过，但必须保留屏幕阅读器可识别的名称、disabled 状态和禁用原因。

## 9. P1-07 禁用原因提示：交互层与业务 enabled 分离

来源：**Qt 可访问性必须新增**；视觉复用现有 Tooltip。

当前禁用按钮同时关闭 MouseArea，导致 `mouse.containsMouse` 无法可靠产生，禁用原因不可见。修复后应满足：

- 视觉 disabled：整体约 45% 不透明度，背景仍为 `bgRaised`，文字 `textMuted`，尺寸不变。
- 业务动作：disabled 时鼠标、Enter、Space 均不得触发 `clicked`。
- 提示命中：独立 hover 层在 disabled 时仍工作，只负责显示说明，不负责业务点击。
- Tooltip：`bgRaised #161F2B`、1 px `#273342`、圆角 6、高 26、文字 10/Regular `#7E8DA1`；与按钮至少间隔 3 px。
- 优先显示在按钮上方；空间不足时翻到下方，不得被父级卡片裁剪。
- `toolTip` 同步到可访问 description；屏幕阅读器读取“控件名称、不可用、原因”。
- 没有禁用原因的控件不得显示空 Tooltip。

范围、全屏、缩小、放大、播放和未接入导航继续保持原有 disabled 状态与既有中文原因；本补丁不启用这些功能。

## 11. 实施与验收步骤

### 11.1 视觉严格匹配

1. 以 1600×1000 客户端内容启动页面，截图时排除系统标题栏。
2. 叠加 Figma 节点 26:972 的 Desktop Bridge 导出，不调用 `get_design_context`。
3. 测量时刻区 x=1060/1328/1394、主按钮 166×38、工具栏 x=656/总宽570、图例 x=660/槽宽104；外框误差不得超过 1 px。
4. 确认 Y轴：对数是唯一工具栏选中项，X轴：股票代码为普通态。
5. 确认默认态截图没有因焦点环、提示层或响应式绑定发生位移。

### 11.2 状态与键盘

1. 对普通、primary、active、disabled 按钮依次验证 default、hover、keyboard focus；焦点环必须独立于 hover/active。
2. 只用键盘从日期开始走完整个 Tab 顺序；Enter/Space 每次只触发一次。
3. 分时 Slider 用左右键推进，读出的值与输入框 `HH:mm` 一致。
4. 对播放、范围、全屏、缩小、放大和未接入导航逐项悬停，确认禁用原因可见且点击无动作。
5. 用 Windows Narrator 或同类工具读取至少一个启用按钮、一个禁用按钮、日期、时刻和 Slider；检查名称、角色、值/状态、禁用原因，不据此宣称全面 WCAG 合规。

### 11.3 响应式

1. 在 `1600×1000` 验证 92 px 单行卡和 Figma 精确坐标。
2. 在 `1599×1000`、`1440×1000`、`1360×1000` 验证 148 px 两行卡和常驻摘要；任何控件不得重叠、裁剪或缩窄。
3. 在 `1359×1000`、`1280×1000`、`1279×1000`、`1120×1000` 验证摘要改为 318 px 抽屉，主图填充，第二行应用按钮始终保留 20 px 右边距。
4. 在每个宽度重复 Tab 导航，焦点环不得被卡片或抽屉遮挡。

### 11.4 工程回归

实施会话完成后运行：

```powershell
cmake --build --preset vs2022-debug --parallel
ctest --preset vs2022-debug --output-on-failure
cmake --build --preset vs2022-debug --target all_qmllint
```

并确认 Scene Graph 散点渲染、hover 命中、筛选版本、快照查询和摘要统计没有因纯布局补丁发生行为变化。

## 12. 完成定义

只有同时满足以下条件，P1 才可关闭：
