## 应用、QML 与持久化

Debug 应用在副屏 1602×1032 启动，主页 `600519` 腾讯 1 分钟模型计数随轮询从 3、12、23 增至 33 根，状态保持“已更新”，窗口检查均为 responding。历史快照页把请求时刻 `09:41` 与解析时刻 `09:37:40` 分开显示，并以“历史快照 / 陈旧约 200 秒”提示，没有把旧批次冒充实时。请求代次的旧响应门控由 `market_snapshot_contract` 和 `realtime_provider_router` 定向测试覆盖；运行界面当前没有直接展示数值 requestId，因此本轮不宣称人工观察到代次值。

应用内写库未通过稳定性门槛。09:30–10:03 日志记录 404 次采集开始、403 次“不完整”和 320 次 `Tick 写入队列已满`，共丢弃 1,665,280 条待写行情。09:30–10:00 仅持久化 81 个快照批次，批次间隔 p50/p95/max 为 4.959/83.990/123.666 秒；全部 81 批均按真实 received/expected 标记不完整。09:46 的人工查询只能解析到 09:37:40，证明积压会直接造成历史查询陈旧，而不只是日志噪声。

进程内存的连续 JSON 采样器因命令引号错误未产出有效文件，不能编造内存 p50/p95。现场抽样从启动后的约 272/275 MiB（工作集/私有）上升到 10:00 的约 444/473 MiB，期间窗口始终响应；30 分钟样本不足以判定泄漏。标题栏关闭后窗口立即消失，但后台采集仍持续超过 30 秒，之后进程自行退出，未执行强制终止；退出生命周期仍不通过本轮验收。

## 验收后边界修复（2026-08-26）

用户确认实时行情只用于显示，不做实时存储；历史行情必须由用户在“本地历史数据”工作区显式点击下载或通过明确导入流程进入 SQLite。控制器已据此移除实时 `appendTick`、`AsyncTickWriter` 和 `appendMarketSnapshot` 路径。最新全市场快照直接驻留内存并更新 `marketSnapshotModel`；历史时刻查询仍只读取已经存在的本地快照，不会把实时观测隐式写入历史库。主页腾讯分钟序列继续仅驻留内存。

本次修复没有删除旧数据库数据，也没有访问网络或 NAS。新增契约测试锁定“实时处理函数不得写库”，并覆盖内存快照可直接进入页面模型且临时数据库保持为空；显式历史下载入口及其缓存复用、校验和入库流程保持不变。最终串行 Debug 全量构建成功，CTest 42/42（79.23 秒）通过，`all_qmllint` 通过；使用隔离临时数据库的原生关闭探针 3.993 秒完成并确认 PID 释放。

修复后尝试以现有大型开发数据库启动一次人工界面复核，但进程在 60 秒内未创建窗口；该进程已按已核验 PID 释放，不能据此宣称完成修复后的盘中视觉验收。当前结论是“实时/历史持久化边界与自动测试通过”，真实 Provider→Router→QML 的修复后盘中复验仍应在下一交易窗口进行。
