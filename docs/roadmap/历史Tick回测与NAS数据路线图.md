# 历史 Tick 回测与 NAS 数据全局路线图

## 目标与不变量

历史回测只接受可追溯的原始 Tick 事实。NAS/虚拟机保存 `YYYYMMDD/代码.csv` 原始文件，本机 SQLite 保存显式同步后的 `raw_trade_ticks`、按需派生 K 线和回测归档。免费实时 1 分钟行情是独立内存数据域，远端日 K 只用于研究缓存；两者都不能在 Tick 缺失时自动成为回测输入。

回测运行期必须离线：选择数据、打开页面和点击回测都不得访问 Provider 或 NAS。可回测 catalog 只包含 `source=raw_tick_cache_v1` 的 A 股数据集；远端 K 线仍通过 `localHistoryDataCatalog` 展示，但不会进入 `localBacktestDataCatalog`。

## 已完成基线

1. **事实与派生层**：逐行流式导入、B/S/M 独立方向、上海时区、A 股交易时段、事务写入和 1–86400 秒按需派生缓存已完成。
2. **NAS 节点 v1**：只读 health/catalog/按日下载、Range、ETag、SHA-256、requestId 门控和本地事务导入已完成。
3. **守护部署**：虚拟机已安装节点脚本和 `deploy/systemd/pptrader-nas-node.service` 用户服务；服务只监听远端回环地址、开机用户会话可恢复，并通过 SSH 本地端口转发访问。部署参数只存在目标机环境文件，不进入仓库。
4. **严格回测路由**：内置与自定义策略统一从选中的 Tick 派生 SQLite 数据集读取，不再调用 `HistoricalDataService`。数据不足时明确拒绝，不回退网络。
5. **真实闭环**：已有真实单日数据形成 4064 条成交、239 根 1 分钟和 49 根 5 分钟 K 线；已用 200 根 1 分钟 K 线完成一次可归档回测和副屏验收。

## 后续阶段

### H1：多日按需同步与容量基线

- **H1A 已完成**：单代码、日期范围 catalog 后的显式多日串行同步；每日期独立下载/校验/事务导入，失败继续，取消和失败项可恢复，不扫描全仓库。
- **H1B 已完成（100 档验收）**：用户明确代码列表的受控 manifest、稳定多代码队列和固定单文件串行写入；已记录 1/10/100 档 catalog、传输、解析、SQLite 与派生耗时。只读全量 manifest 已验证 5186/5207 个文件；500 与 5207 的真实写库按用户决定留待后续，不能描述为已实测。
- **H1C 已完成**：队列计划通过版本化、原子 JSON 跨进程恢复；运行中条目重启后转为可重试取消项，成功项不重复处理。客户端展示 SHA-256 缓存命中，并提供显式缓存统计与保留期清理；清理只触及受管暂存 CSV，不删除 SQLite 事实。恢复、扫描和清理均不自动联网或后台下载。manifest 摘要索引缓存和字节级断点续传仍属于后续优化。

### H2：回测数据集身份

- 将原始日期集合、聚合算法版本、周期和 Tick 指纹组合为不可变数据集版本。
- 归档结果展示数据来源日期范围、原始行数、派生根数和缺口，不以当前缓存解释历史结果。
- 增加数据集完整率、交易日覆盖和坏行质量门槛。

### H3：横向回测与组合研究

- **H3A 已完成**：同一内置策略多品种结果矩阵、独立工作线程、最多 20 个活动引擎、SQLite 只读逐项装载、requestId 门控、取消和单项失败隔离。完成项只保留轻量摘要，不把 5000 份曲线/成交长期留在内存。
- **H3B 待完成**：以 H1 同步后的真实多标数据重测 1/10/100/500/5207 标的读取—计算耗时，并为用户明确选择的单项结果提供曲线/成交按需归档和中断恢复。
- **H3C 待规划**：组合资金、横截面调仓、组合级成交约束与风险；不得把 H3A 的独立初始资金任务矩阵描述成组合回测。

计算容量预检已经完成：本机 Release 使用真实单日 239 根 Tick 派生 K 线形状，在 20 个有界活动引擎下完成 5207 个独立任务需 2.710 秒，50,000 个压力任务需 25.236 秒，均为零失败。H3A 已把该并发预算落为产品后端契约，但当前真实本地 catalog 仍只有一个可回测样本，因此不代表真实 5207 份装载、归档或组合回测已完成；详细口径见 `docs/backtest-capacity-baseline.md`。

### H4：生产 NAS 能力

- 由反向代理提供 HTTPS 与认证轮换；增加健康监控、审计、备份和容量告警。
- 评估 Parquet/Zstd、断点续传状态机和变更通知。通知只提示 catalog 变化，不自动下载或运行回测。

## 验收规则

每阶段必须使用临时 SQLite/fake 节点完成无网络测试，再以真实 NAS 数据做受控验证；串行执行 Debug 构建、CTest、QML lint，并记录数据规模、耗时、完整率、失败保护和副屏截图。仓库、日志、截图说明和测试不得保存主机、用户名、密码或数据仓库绝对路径。
