# 多股自定义回测（单只 → 多股横截面）

> 状态：计划已确认，待实施。先文档、后代码。
> 决策记录（2026-08-15）：策略形态覆盖「横截面选股/轮动」与「多股价差/相对值」两类；数据粒度以分钟级为主、日线兼容；实施从抽取 `PortfolioExecutor` 开始。

## 目标

在现有自定义策略回测体系上，扩展出统一的多标的回测能力，分两步：

1. **单只股票自定义回测** —— 打磨成完整闭环，并作为多标的 `n=1` 的特例统一进同一套引擎。
2. **多只股票自定义回测** —— 策略在**同一时刻**读取 n 只股票对齐后的价格参与计算，据此回测组合表现。

## 定位与不变量

- 本方向落在路线 2（`A股自定义策略回测.md`）与路线 3（`A股组合横截面.md`）交界：把单标的 DSL 回测升级为多标的，把组合横截面从「研究/固定权重」升级为「策略信号驱动」。
- 回测仍必须**离线、可追溯**：选择数据、打开页面、运行回测都不得访问 Provider 或 NAS；每条腿的数据集身份（sha256）必须校验并在归档中保存。
- 自定义策略仍是声明式 JSON，不执行本机 C++/Python/JS、文件、网络或动态模块；`executionScope` 仍为 `backtest_only`。
- 免费实时 1 分钟行情是独立内存域，不参与回测；回测输入只来自 `source=raw_tick_cache_v1` 的派生 K 线。

## 代码图调研结论（2026-08-15，基于 codebase 索引）

以下结论来自对调用图（CALLS 边）的核实，作为本计划的事实基础：

1. **`PortfolioBacktestEngine::run` 是自包含静态纯函数**，唯一生产调用者是 `PortfolioBacktestService::request`（另有 `tst_portfolio_backtest` 与 `probe_mootdx_snapshot`）。它只依赖内部 `normalizedWeights` 与 `PortfolioTypes`，不持有引擎状态。→ 抽取 `PortfolioExecutor` 干净、可回归。
2. **单标的回测链**：`TradingController.runStrategyBacktest / runCustomStrategyBacktest / runSelectedLocalCustomStrategyBacktest` 是入口；`BacktestEngine::processNextCandle` 逐 Bar 推进 → 策略 `onCandle` → `handleStrategySignal` → `openPosition/closePosition`。策略实例由 `start(config, candles, providedStrategy)` 外部传入，不经过 `BacktestStrategyRegistry` 创建自定义策略。
3. **组合回测链**：`TradingController.runPortfolioBacktest → PortfolioBacktestService.request → PortfolioBacktestEngine.run`；完成归档走 `handlePortfolioBacktestCompleted → savePortfolioBacktestArchive`。`PortfolioBacktestService` 是 worker 线程异步服务。
4. **横截面链是快照导向、与回测无交集**：`TradingController` 构造时 `CrossSectionalIndicatorEngine.addIndicator`，`handleMarketSnapshot` 时 `AShareRelativeStrengthIndicator.calculate`；`CrossSectionalIndicatorEngine.calculate` 仅被 `tst_cross_sectional` 调用。→ 需要新建「回测逐 Bar 版」，而非改造快照版。
5. **DSL 求值链是单标的**：`CustomStrategyCompiler.compile → PlanBuilder.compileIndicator/compileOperand/compileCondition`；`CustomBacktestStrategy.onCandle → CustomIndicatorRuntime.append + evaluateCondition → evaluateOperand(row, candle) → CustomIndicatorRuntime.value`。一个 `CustomIndicatorRuntime` 实例对应一条 candle 序列。→ 多股需动「编译器 + 策略 + 运行时」三层。
6. **`AShareUniverseLoader::load`**（由 `TradingController.reloadAShareUniverse` 与 `main` 调用）加载全 A 股股票池，`venueForCode` 判定沪深 venue。→ 多股 universe 选择可复用。

## 现状盘点

**已具备、可直接复用：**

| 能力 | 位置 | 复用方式 |
| --- | --- | --- |
| 组合执行骨架 | `PortfolioBacktestEngine::run`（静态纯函数） | 抽取 `PortfolioExecutor`，先卖后买/整手/费用/滑点/T+1/stale 语义保留 |
| 组合服务/归档 | `PortfolioBacktestService`、`savePortfolioBacktestArchive` | 多股服务与归档复用同一 worker 线程 + 事务模式 |
| 单标的指标运行时 | `CustomIndicatorRuntime` | 多股时每条腿一个实例 |
| DSL 编译框架 | `CustomStrategyCompiler`（`PlanBuilder`） | 扩展操作数/指标，沿用白名单、三值逻辑、预热期、未来数据拒绝 |
| 横截面统计口径 | `AShareRelativeStrengthIndicator`（rank/zscore/percentile） | 改造成回测逐 Bar 版，统计口径不变 |
| 数据集身份 | `BacktestDatasetService`、`BacktestDatasetIdentity` | 多股逐腿校验复用 |
| 股票池加载 | `AShareUniverseLoader` | universe 代码列表/筛选的候选来源 |
| 数据读取 | `SqliteLocalDataStore` | 按 symbol 读同周期 K 线 |

**关键缺口：**

1. DSL 无横截面操作数（无法引用同一时刻其他股票/横截面统计）。
2. 数据对齐粒度错配：`PortfolioBacktestEngine` 按**交易日**对齐；多股联合需要按 **bar 时间戳**对齐（分钟级）。
3. 无多股信号回测引擎：组合引擎只做固定权重再平衡，不接策略信号。
4. 横截面指标无回测序列版（现有基于一次性 `MarketSnapshot`）。

## 总体设计（单只 = 多只 n=1 的统一模型）

```
对齐数据层  AlignedBarSeries（QHash<symbol, Candle> 按时间戳对齐成帧序列）
      │
策略层      CrossSectionalCustomStrategy（每帧输入 n 股同刻价格 + 各自历史）
      │
执行/估值层  PortfolioExecutor（先卖后买、整手、费用、滑点、T+1、缺报价 stale）
```

**架构决策（依据代码图调研）：**

- 多股引擎采用**同步纯函数**（`static run(...)`），跑在 `PortfolioBacktestService` 一类的 worker 线程里，**不是** `BacktestEngine` 的 QTimer 事件循环。理由：多股回测是批量离线计算，无 UI 交互；`PortfolioBacktestEngine::run` 已验证这条路线。
- 引擎内部**按帧索引推进**，天然支持 `replayBar(frameIndex)` 逐帧回放（纯函数 + 帧序列），同时满足向导步骤 7 的回放需求。
- 策略实例由编译器产出后**外部传入**（参考 `BacktestEngine::start(config, candles, providedStrategy)`），不依赖 `BacktestStrategyRegistry`。
- **单只回测** = universe 只有 1 个 symbol，策略只读自身历史（等价于现有 `BacktestEngine`，走统一引擎）。

## DSL v3 设计要点

覆盖两类策略的同一套语法：

```json
{
  "schemaVersion": 3,
  "strategyId": "custom_cross_momentum",
  "version": 1,
  "name": "横截面动量轮动",
  "market": "A股",
  "executionScope": "backtest_only",
  "universe": { "mode": "explicit", "symbols": ["600519", "000001", "600036", "601318"] },
  "crossIndicators": [
    { "alias": "mom_rank", "indicator": "RANK", "of": { "indicator": "ROC", "period": 20 }, "ascending": false },
    { "alias": "close_z", "indicator": "ZSCORE", "of": { "field": "close" } },
    { "alias": "peer_spread", "indicator": "PEER", "symbol": "600519", "field": "close" }
  ],
  "selection": { "mode": "topN", "rankBy": "mom_rank", "count": 3 },
  "entry": { "op": "gte", "left": { "cross": "mom_rank" }, "right": { "constant": 1 } },
  "exit": { "op": "lt", "left": { "cross": "mom_rank" }, "right": { "constant": 3 } },
  "position": { "type": "equalWeight" },
  "risk": { "stopLossPercent": 5, "tPlusOne": true }
}
```

- `RANK`/`ZSCORE`/`PERCENTILE`/`MEAN`/`MEDIAN` 是横截面统计，在**同一帧的 n 只股票之间**计算；`PEER` 引用指定股票的字段（价差/比值）。
- 单标的时序指标（`SMA`/`ROC`/`VWAP`/`PP_FLOW` 等）继续由 v2 `series` 表达，每条腿独立求值。
- `position` 首期支持 `equalWeight`（等权）与 `fixedWeight`（显式权重）；后续可接向导步骤 5 的 `fixedAmount`/30% 市值封顶。

## 数据对齐语义（分钟级为主、日线兼容）

- 帧按 bar `startTime` 升序；`periodSeconds` 一致才允许进入同一回测，否则拒绝。
- `periodSeconds=86400` 即日线，是同一引擎的粗粒度退化，不单独建一套。
- 停牌/缺失：`absent` 腿不参与该帧横截面统计；持仓估值前向填充并标记 `stale`；连续缺失超过阈值的行为留待阶段 2.1 实测后定义（先记录，不伪造）。

## 验收规则

- 每阶段：临时 SQLite/fake 数据单测 + 真实样本受控验证 + 串行 Debug 构建 + CTest + `all_qmllint`。
- 数据质量：对齐缺失/停牌/stale 有明确可见状态，不伪造成交。
- 身份可追溯：多股回测结果携带每条腿的 `datasetVersion`（sha256），归档可恢复。
- 确定性：相同 universe、策略版本、数据版本、参数与规则产生相同结果。
