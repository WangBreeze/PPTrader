# 原始 Tick 异步归档验收（H3B.18）

## 结论

批量回测单项归档已从 UI 线程迁入独立工作线程。`TradingController` 只把保留器中的共享只读结果句柄、结果 ID 和完成时间提交给 `AsyncBacktestArchiveService`；权益曲线复制、延迟 Tick 快照物化、身份复验和 SQLite 事务写入均在工作线程完成。结果通过 requestId 返回，Controller 只接受当前代次，完成后才更新批量结果和归档列表。

QML 暴露归档中的标的、loading、请求/解析 requestId、结果 ID 和错误。归档期间不显示顶层模态窗口，工作台仍可操作，但为避免重复副作用，其他归档按钮暂时禁用。数据身份变化会返回明确错误，既有缓存和归档不受影响。

## 验证

- 临时 SQLite 中，异步请求提交后没有同步完成信号；后台恢复 60 条原始 Tick 并可通过归档接口完整读取。
- 回测完成后追加一条 Tick，后台物化因逐日身份变化而拒绝，目标 result ID 不可读取，没有半个归档。
- 批量结果保留器使用共享只读快照；结果从列表缓存淘汰后，已经提交的归档任务仍持有安全生命周期。
- Debug 串行全量构建通过；CTest 43/43 通过（68.11 秒）；`all_qmllint` 通过。
- 使用隔离空数据库实际启动 `PPTrader · 量化交易工作台`，窗口创建成功并正常关闭，stdout/stderr 均为空。本阶段未访问 NAS 或外网。

## 边界

异步归档不可取消，同一时刻只接受一个显式归档请求。应用退出或数据库迁移会等待正在执行的归档完成，以保持 SQLite 事务一致性。归档仍需暂时物化完整 Tick 快照，因此工作线程峰值内存仍与单条归档的输入规模相关；本阶段 fixture 只验证并发契约和原子性，不是跨月真实数据性能验收。固定留出、多折、参数敏感性及逐 Tick 权益结果的内存上界仍待后续处理。
