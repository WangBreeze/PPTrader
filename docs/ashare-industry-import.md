# A 股行业分类 CSV 导入契约

最后更新：2026-08-22

## 范围与触发

行业导入只处理用户在“指标与策略 → 数据管理”中显式选择的本地磁盘或已挂载盘符 CSV。选择文件、打开页面、刷新审计历史均不会读取 CSV、访问网络或访问 NAS。预览和确认在后台线程执行，不阻塞 QML，也不使用顶层模态 loading。

## 文件格式

文件必须是严格 UTF-8，固定表头如下：

```csv
symbol,name,venue,industry_code,industry_name,effective_from,effective_to
600519,贵州茅台,SSE,C15,酒类制造,2020-01-01,
000001,平安银行,SZSE,J66,银行,2020-01-01,2026-12-31
```

- 当前只接受沪深六位 A 股代码；`venue` 必须与代码前缀一致。
- 日期使用 `YYYY-MM-DD`；空 `effective_to` 表示开放区间。
- 同一标的的有效期不得重叠；任一错误会拒绝整个数据集。
- 单行上限 1 MiB，解析使用 `QFile/QIODevice::readLine`，不会一次读入整文件。
- `classification`、`source`、`sourceVersion` 由用户如实声明，只允许 1–80 位字母、数字、点、冒号、下划线或连字符。

## 两步提交与身份

1. “预览校验”逐行解析、检查 SQLite 身份并计算文件 SHA-256 与规范化数据集 SHA-256，不写库。
2. “确认导入”必须匹配最近预览的文件、分类体系、来源和版本，并重新计算文件 SHA-256；文件变化会被拒绝。

相同分类、来源、版本和内容会复用既有数据集。同一分类、来源和版本出现不同内容时，必须填写修订原因；新数据集只增不改，并保存前序数据集 ID。schema v13 保存文件名、读取行数、记录数、修订原因和前序身份；成员与父数据集在同一事务提交。

## 事实边界

测试使用临时 CSV 和 SQLite fixture，只证明解析、事务、哈希及修订契约。项目没有自动网页抓取、官方 API 客户端或定时更新任务；用户填写的来源不构成官方认证。真实生产使用前仍须确认分类体系授权、历史覆盖、更新频率与再分发限制。
