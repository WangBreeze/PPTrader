本轮全天验收结论为**未完成（下午样本无效）**。09:30–11:30 的两个上午分段均通过，500 个不同 A 股的已接收报价全部完成策略计算；13:00–15:00 的探针却由未申请外网权限的自动化命令启动，子进程继承 Codex 沙箱的网络禁用，因此每轮七个请求分块均在本机被拒绝并呈现 `Permission denied`。下午 119 个 0/500 批次不能用于判断腾讯服务可用性，也不能把当天整体判成腾讯单源失败。

本次验证的是“同时监控 500 只 A 股并运行内存信号策略”，不是“同时回测 500 只”。两者共享策略算法，但数据时钟、状态生命周期、故障模式和验收指标不同。

## 安全与数据边界

- 从 `data/astock_cache.json` 加载 500 个不同的有效沪深 A 股代码。
- 通过现有 `TencentMarketDataProvider` 每 60 秒获取一次公开报价，不新增行情协议。

- 只计算信号，不创建订单端口、不调用券商、不审批执行，`persistenceWrites=0`。
- 实时行情和信号只驻留内存，不写入 SQLite；未访问 NAS。

| Codex 默认网络沙箱 | 0/1 | 102 ms | `批次 0：Permission denied` |
| 显式获准访问外网 | 1/1 | 269 ms | 0 |

两次只改变外网权限。受限样本 SHA-256 为 `48B79DFE66D1D5116A9F73370F63B2A8F62B7F4C83E510ABADD49AC4B5F0D88E`，放行样本为 `A2C6347209380816D665AAB215F6580E0BD75CD27901D4BD04BEA919C8BCDD11`。`TencentMarketDataProvider` 在 `QNetworkReply::error()` 非零时原样记录 `errorString()`；因此这里的文本只是 Qt 对本机网络拒绝的表达，不能据它推断 HTTP 403 或腾讯限流。完整诊断见 `docs/permission-denied-diagnosis-2026-08-28.md`。
